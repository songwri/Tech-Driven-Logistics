# TDL Lab 백엔드 설정 (서버 비용 0원 · 토큰 불필요)

사이트는 GitHub Pages 정적 호스팅이라 서버가 없습니다. Google Apps Script 웹앱을
배포하면 **URL 하나만** 사이트에 넣으면 되고, 토큰·API 키를 사이트 코드에 두지
않습니다. 시트가 그대로 관리자 화면이 됩니다.

## 설계 구조

**서버를 빌리지 않으므로 월 비용이 발생하지 않습니다.** 구글 계정의 Apps Script
할당량(하루 메일 100통, 무료 계정 기준) 안에서 동작합니다.

```
[방문자 브라우저]
   │
   │ ① 예약 신청 (POST)                     ② 방명록 작성 (POST)
   ▼                                          ▼
┌──────────────────────────────────────────────────────┐
│  Google Apps Script 웹앱  (무료 · 상시 대기 · URL 1개)   │
│  · 요일/투어/시간대 검증 (월·수·금)                       │
│  · 승인된 일정과 공간·시간이 겹치는지 검증                 │
│  · 이름/소속 마스킹                                     │
└───────┬───────────────────────────────┬──────────────┘
        │                               │
        ▼                               ▼
  MailApp.sendEmail            스프레드시트 append
  담당자 메일 (MAIL_TO · CENTER_MAIL_TO)  (guestbook / visit_requests 시트)
  · 예약: 투어별 담당자 메일 수신  · 예약: 상태(대기/승인/거절) 보관
  · 방명록: 메일 없음              · 방명록: 사이트 표시용 원본
        │                               │
        │ ③ 메일의 [확정] 버튼            │ ④ 방명록 + 예약불가 슬롯 조회 (GET)
        └──────► 상태 '확정' ────────────►│
                                          ▼
                      [사이트 최하단 방문자 기록 / 예약 달력]
```

**예약** 알림은 접수 즉시 투어 종류에 따라 두 담당자 그룹에 나뉘어 갑니다. **방명록은 메일을 보내지 않습니다**
(관리자 페이지의 방명록 탭에서 확인).

| 투어 | 수신자 |
| --- | --- |
| 종합 투어 | 센터 투어 담당자 + TDL 투어 담당자 (중복 주소는 한 번만) |
| TDL Lab 투어 | TDL 투어 담당자 |
| 센터 투어 | 센터 투어 담당자 |

담당자 주소는 스크립트 속성에 둡니다 (프로젝트 설정 → 스크립트 속성, 쉼표로 여러 명, 저장 즉시 적용).
`MAIL_TO` = TDL 투어 담당자, `CENTER_MAIL_TO` = 센터 투어 담당자.
이 저장소는 공개라 직원 메일 주소를 코드에 적지 않고 속성에만 둡니다. `MAIL_TO` 가 비어 있으면
`Code.gs`의 `DEFAULT_MAIL_TO`로, `CENTER_MAIL_TO` 가 비어 있으면 TDL 담당자에게 대신 갑니다.
신청자에게 가는 승인 · 거절 메일의 회신 주소는 그 예약의 알림을 받은 담당자들입니다.
보내는 사람 이름은 "메가와이즈 + TDL 방문관리"입니다.
공용 메일함 · 배포 목록은 외부(구글 계정) 발신 메일을 막는 경우가 있어, 막힌다면 담당자 개인 주소를
`MAIL_TO`에 나열하거나 IT팀에 해당 주소의 외부 발신 허용을 요청하세요.
메일의 회신 주소(Reply-To)가 신청자 이메일로 지정되어 있어, 받은 메일에서 바로
**회신 버튼만 누르면 신청자에게 답장**이 갑니다. 시트 기록은 이력 확인용이며 지워도
메일 발송에는 영향이 없습니다.

**방명록은 메일만으로는 처리할 수 없습니다.** 사이트 하단에 목록으로 보여줘야 하니
어딘가에 남아 있어야 하고, 그 저장소가 시트입니다. 시트는 무료라 추가 비용은 없습니다.

| 저장 위치 | 내용 |
| --- | --- |
| `guestbook` 시트 | 방명록. 표시용(마스킹) 값과 실명·실제 회사명이 함께 기록됩니다. 평가는 0.5점 단위(0.5~5), 팀명은 11번째 `팀` 열(선택 입력, 기존 시트는 재배포 후 첫 요청에서 열 제목이 자동 추가)입니다. |
| `visit_requests` 시트 | 예약 신청. 투어·일정·방문 유형(내부/고객)·투어 언어·통역 동반·업종·목적·담당자(담당(실) 포함)·방문자 명단·상태·관리자 메모. |
| `blocked` 시트 | 휴무일 등 수동으로 막을 날짜/시간대. |
| 팀 메일 | 예약 등록 즉시 자동 발송 (방명록은 메일 없음). |

사이트로 나가는 것은 **마스킹된 값뿐**입니다. 실명과 연락처는 시트와 메일에만 남습니다.

## 설정 (약 5분, 1회)

1. [sheets.new](https://sheets.new) 로 새 스프레드시트를 만듭니다. (이름 예: `TDL Lab`)
2. 상단 메뉴 **확장 프로그램 → Apps Script**
3. 편집기의 기본 코드를 지우고 이 폴더의 `Code.gs` 내용을 붙여넣습니다.
   - 수신 메일 주소는 코드가 아니라 **프로젝트 설정 → 스크립트 속성**의 `MAIL_TO`(TDL 투어 담당자), `CENTER_MAIL_TO`(센터 투어 담당자)로 정합니다. (쉼표로 여러 명, 저장 즉시 적용, 재배포 불필요)
4. 우측 상단 **배포 → 새 배포**
   - 유형: **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 → 권한 승인(본인 구글 계정)
5. 발급된 **웹 앱 URL**을 복사합니다.
   (`https://script.google.com/macros/s/…/exec` 형태)
6. **관리자 키 설정** — 편집기 왼쪽 **⚙ 프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**
   - 속성: `ADMIN_KEY`
   - 값: 관리자만 아는 충분히 긴 임의 문자열 (20자 이상 권장)
   - 관리자 대시보드(`/admin/`) 로그인에 이 값을 입력합니다. 코드나 저장소에는 넣지 않습니다.
7. **가져오기 암호키 설정** — 같은 **스크립트 속성**에 `IMPORT_KEY` 를 추가합니다.
   - 관리자 페이지의 *기존 이력 가져오기*는 이 암호키를 입력해야만 업로드됩니다 (원본 데이터 보호).
   - 가져오기는 기존 행을 지우거나 덮어쓰지 않고 `visit_requests` 마지막 행 아래에 이어서 추가하며,
     이미 있는 방문(날짜 + 업체 + 시간)은 건너뜁니다.

8. **(권장) 응답 속도 트리거 설치** — 편집기 상단 함수 선택에서 `installWarmUp` 을 고르고 **실행**(권한 승인)합니다.
   - 5분마다 예약 화면용 일정 캐시를 미리 만들고 웹앱을 깨워 두어, 예약 · 관리자 화면의 첫 응답이 빨라집니다.
   - 일정 캐시는 예약 승인 · 일정 막기 등 쓰기가 일어나면 즉시 지워지고, 시트를 직접 고친 경우에도 최대 5~10분 안에 반영됩니다.
   - 신청 시 중복 검사는 캐시가 아닌 시트를 직접 읽어 판단합니다.

## 사이트에 연결

GitHub 저장소 → **Settings → Secrets and variables → Actions → Variables** 탭 →
**New repository variable**

- Name: `VITE_LAB_API`
- Value: 위에서 복사한 웹 앱 URL

저장 후 다음 배포부터 예약·방명록이 실제로 접수됩니다.
(변수를 설정하기 전까지 방명록은 브라우저 로컬 저장으로만 동작하고, 예약은
"서버 연결 전" 안내가 표시됩니다.)

## 코드를 수정한 경우

Apps Script 편집기에서 **배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포**를
해야 반영됩니다. URL은 그대로 유지됩니다.

## 방명록 내리기 (악성 글 삭제)

방명록은 시트가 원본이고 사이트는 그걸 그대로 읽어갑니다. 그래서 **시트에서
내리면 사이트에서도 즉시 사라집니다.** 배포를 다시 할 필요 없습니다.

두 가지 방법이 있습니다.

**1) 숨기기 (권장)**
`guestbook` 시트에서 해당 행의 **`숨김`** 열에 아무 값이나 넣으면(예: `숨김`)
사이트 목록에서 빠집니다. 원본은 남아 있어서 나중에 확인하거나 되돌릴 수 있고,
`숨김` 열을 비우면 다시 표시됩니다.

**2) 완전 삭제**
행 번호에서 우클릭 → **행 삭제**. 되돌릴 수 없습니다.

시트를 열면 상단에 **`TDL Lab`** 메뉴가 생깁니다. 행을 선택하고
`TDL Lab → 선택한 방명록 숨기기 / 다시 표시` 를 누르면 열을 직접 건드리지 않고
처리할 수 있습니다. (메뉴가 안 보이면 시트를 새로고침하세요.)

방문자 화면은 새로고침하면 반영됩니다.

**3) 관리자 페이지에서 (가장 편함)**
`/admin/` 의 **방명록** 탭에서 실명 · 실제 소속과 함께 목록을 보고 **숨기기 / 다시 표시 / 삭제**를 누릅니다.
위 시트 방식과 같은 `숨김` 열을 쓰므로 서로 섞어 써도 됩니다. 이 기능은 `Code.gs` 기능 수준 4(`API_LEVEL`)가
필요해서, 코드를 붙여넣고 **기존 배포를 새 버전으로 재배포**해야 합니다. 이전 버전이면 방명록 탭에 재배포 안내가 뜹니다.

## 방문 예약 규칙

투어 종류와 시간은 `Code.gs` 상단 `TOURS` 와 `src/lib/visit.ts` 의 `TOURS` 에 같은 값으로
정의되어 있습니다. 바꿀 때는 **두 곳을 함께** 수정하세요.

| 투어 | 시간대 (월·수·금) | 사용 공간 |
| --- | --- | --- |
| 종합 투어 | 09:30–11:30, 13:00–15:00 | 앞 1시간 센터 → 뒤 1시간 TDL Lab |
| 센터 투어 | 09:30–10:30, 10:30–11:30, 13:00–14:00, 14:00–15:00, 15:00–16:00 | 센터 |
| TDL Lab 투어 | 10:30–11:30, 14:00–15:00 | TDL Lab |

**당일 · 익일 신청은 받지 않습니다** (오늘 +2일부터 선택 가능). 기준을 바꾸려면 `Code.gs` 의
`MIN_LEAD_DAYS` 와 `src/lib/visit.ts` 의 `MIN_LEAD_DAYS` 를 함께 수정하세요. 관리자 대시보드에서
일정을 수정할 때는 이 제한이 적용되지 않습니다.

센터와 TDL Lab은 각각 한 번에 한 팀만 받는다고 보고 **공간 단위로 겹침을 판정**합니다.
예) 종합 투어 09:30–11:30 이 승인되면 같은 날 센터 09:30–10:30, Lab 10:30–11:30 은 신청할 수
없고, 센터 10:30–11:30 은 가능합니다.

## 관리자 대시보드 (`/admin/`)

`https://songwri.github.io/Tech-Driven-Logistics/admin/` 에서 `ADMIN_KEY` 로 로그인합니다.

- **예약 대시보드**: 상단 월간 달력(투어 색 · 상태 톤) + 하단 예약 요청 목록.
  날짜를 누르면 그날 예약만, 행을 누르면 상세/수정 창이 열립니다.
  행 색상 — 대기중: 흰색 · 승인됨: 그린 · 거절됨: 회색.
- **승인/거절**: 목록·상세 창·신청 메일의 버튼 어디서든 가능합니다. 승인 시 다른 승인
  건과 겹치면 거부하고, 상태가 바뀌면 신청 담당자에게 결과 메일이 갑니다.
- **방명록**: 전체 · 공개 · 숨김 건수와 공개 글 평균 평가, 목록(실명 · 소속 · 메시지), 숨기기 · 삭제, 검색, 엑셀 내려받기.
- **방문 통계**: 연도 선택 + 연간/월별 조회, 전체 신청/승인 건 기준 전환.
  방문 목적 · 고객 구분 → 월별/연도별 추이 → 투어 종류 · 업종 → 직무 순으로 배치했습니다.

`VITE_LAB_API` 가 설정되지 않은 빌드(로컬 개발 등)에서는 로그인 없이 **데모 데이터**로
동작하며, 변경 내용은 그 브라우저에만 저장됩니다.

## 예약 승인 → 그 시간대 자동 마감

예약 신청 메일의 **[확인하고 승인 · 거절하기]** 버튼을 누르면 관리자 페이지에서 그 예약의 상세
화면이 열립니다(`/admin/?review=<예약번호>`). 관리자 키로 로그인한 뒤 **승인** 또는 **거절**을 누릅니다.

- 메일 링크만으로는 승인되지 않습니다. 메일이 전달되거나 회사 메일 보안 스캐너가 링크를 미리 열어도
  예약 상태가 바뀌지 않고, 배포 주소가 여러 개여도 관리자 페이지는 사이트가 쓰는 주소로만 요청합니다.
- 예전 메일의 승인/거절 링크는 상태를 바꾸지 않고 해당 예약의 관리자 화면으로 안내합니다.
- **승인**하면 `visit_requests` 시트의 상태가 `승인`으로 바뀌고, 사이트 예약 화면에서
  **겹치는 시간대가 선택 불가**가 되며, 신청 담당자에게 확정 메일이 발송됩니다.
- **거절**하면 상태가 `거절`이 되고 그 시간대가 다시 열립니다.
- 시트에서 상태 열을 직접 `승인` / `거절` / `대기` 로 바꿔도 동일하게 동작합니다
  (이 경우 결과 메일은 발송되지 않습니다).

**통계와 삭제**

- **거절된 예약은 방문 통계에서 제외**됩니다(처음부터 거절이든 승인 후 거절로 바꾼 것이든).
  통계표의 '거절' 열과 승인률 계산에만 쓰입니다.
- 관리자 페이지 예약 상세의 **삭제**는 목록 · 통계 · `visit_requests` 시트의 해당 행을 모두 지웁니다.
  되돌릴 수 없으니, 기록을 남기려면 삭제 대신 거절을 쓰세요.

프론트 화면을 우회해 신청이 들어오더라도 서버에서 한 번 더 확인해 겹치는 일정은 접수를
거부합니다.

**휴무일·행사일처럼 예약과 무관하게 막을 날짜**는 `blocked` 시트에 적습니다.
시간대를 적으면 그 시간에 센터·Lab 모두 막히고, 비우면 하루 전체가 막힙니다.

## 이전 버전에서 올라온 경우

이전 버전의 `reservations` 시트(10:00/14:00 두 시간대)는 그대로 두고, 새 신청은
`visit_requests` 시트에 쌓입니다. 코드를 붙여넣은 뒤 **새 버전으로 재배포**하고
`ADMIN_KEY` 를 설정하면 됩니다.

## 문제 해결: 메일은 오는데 승인 링크가 "예약을 찾을 수 없습니다"

1. **배포된 코드 버전 확인** — 웹앱 주소 뒤에 `?action=version` 을 붙여 열면 코드 버전이 보입니다.
   `Code.gs` 상단 `CODE_VERSION` 과 같지 않으면 재배포가 안 된 것입니다(배포 관리 → 편집 → 새 버전).
2. **관리자 페이지 → 서버 진단** — 예약이 실제로 저장되는 스프레드시트(링크), 탭, 제목 행 상태,
   저장된 예약 수와 토큰 유무, 메일 버튼이 가리키는 주소를 보여줍니다. 지금 보고 계신 시트와
   "저장 스프레드시트"가 다르면 그 링크로 여세요.
3. 메일 버튼은 관리자 페이지로 연결되므로 웹앱 배포가 여러 개여도 승인에는 영향이 없습니다.
   다만 사이트가 쓰는 배포(`VITE_LAB_API`) 하나만 남기고 나머지는 **보관처리(Archive)**하는 것을 권장합니다.

예약 저장과 승인은 스크립트 잠금으로 한 번에 하나씩 처리되어, 동시에 들어온 요청이 서로의
행을 덮어쓰지 않습니다. 새 메일의 승인 링크에는 예약번호(id)가 함께 들어가 id 로 찾습니다.
