### F-03 파트너사별 실적 · 기존 예약을 파트너로 바꾸기 🔴

**A. 파트너사별 실적 (통계 화면 하위 표)**

- 대상: `Category = 고객 방문` 이고 `ClientType = 파트너사 소개 고객` 인 건 (조회 기간 · 센터 범위 필터는 다른 통계와 동일).
- **파트너사 묶기 키**: 이름을 소문자로 바꾸고 공백 · `(주)` · `㈜` · `주식회사` 를 제거한 값. 키가 같으면 같은 파트너사 (`LG 전자` = `lg전자` = `(주)LG전자`).
- 이름이 비어 있으면 `(파트너사명 미입력)` 으로 묶음.
- 표시 이름: 그 파트너사의 **가장 최근 방문**에 적힌 표기.
- 열: 순위 · 파트너사 · **소개 방문 건수** · **방문 인원**(`Heads` 합계) · **소개 고객사 수**(같은 업체는 1곳, 업체명도 같은 규칙으로 정규화) · 최근 방문일.
- 정렬: 건수 ↓, 방문 인원 ↓, 이름(가나다). 상위 10곳 + `전체 n곳 보기` 토글. 줄을 누르면 그 파트너사가 소개한 방문 목록.
- 방문 유형 열에 `고객·파트너사` 추가 (F-02-7 과 연결).
- 통계 엑셀 내보내기에는 시트 `파트너사별(기간)` 추가 — Power Apps 는 엑셀 내보내기를 제외했으므로 **화면 표시만**.

**B. 기존 예약을 파트너로 바꾸기 (관리자)**

- 관리자 요청 상세에서 `고객 유형` 을 **빠른 편집**(전체 수정 창을 열지 않고)으로 바꿀 수 있음: 기존 / 신규 / 파트너사 + 파트너사명.
- 파트너사명 입력칸에는 **이미 기록된 파트너사 이름을 많이 소개한 순으로 제안** (같은 곳이 다르게 적히는 것을 막는 용도).
- 수정은 목록 상태(승인 · 완료 등)를 바꾸지 않음. 후기 메일 발송 기록 등 다른 열은 보존.

### P-01 화면 구조: 본문 스크롤 · 글자 · 큰 모니터 폭
- **왜**: 1366×768 노트북에서 실제 쓸 수 있는 높이는 약 600px. '크기 조정' 을 켜 두면 앱이 78% 로 줄어 글자가 읽기 어렵고, 큰 모니터(1920)에서는 반대로 1.24~1.4배로 커져 달력 하나가 화면을 꽉 채움.
- **무엇**: 화면은 **머리말(메뉴) 고정 + 가운데 본문(스크롤) + 바닥 버튼(신청 화면) 고정**. 본문은 `con?Body`(세로 자동 레이아웃 컨테이너, 넘치면 스크롤) 안의 `con?Page`. 글자는 최소 9pt(로고 제외), 길어지는 목록 스크롤바 표시, 일정 막기 창을 창 가운데에. **창이 1366 보다 넓으면 본문 폭을 `kx` 배(최대 `MaxStretch` = 1.3)로 늘림**(높이는 늘리지 않음).
- **어디에**: `App.Formulas.txt` 의 `sw` · `sh` · `MaxStretch` · `kx` · `pw` · `ox`, 화면 6개 전부(`con?Body` / `con?Page`, 좌표는 `24 + 416 * kx`, `376 + 400 * (kx - 1)` 식).
- **주의 (설정)**: 앱 설정(⚙) → 디스플레이에서 **"크기 조정" · "가로 세로 비율 잠금" 끄기**. 이 설정은 YAML 에 담기지 않으므로 직접 꺼야 함. 새 좌표를 넣을 때 고정 숫자 대신 `kx` 를 써야 큰 모니터에서 늘어남. `AutoLayout` 컨테이너 속성이 버전에 따라 오류면 README 13절 대처 방법.

### P-02 대기 신청이 시간을 차지 + 신청 직전 재확인 + 동시 신청 방지
- **왜**: 웹은 서버 잠금(LockService) 안에서 겹침을 다시 확인한 뒤 저장. Power Apps 는 서버 코드가 없어 달력을 연 뒤 다른 사람이 잡은 시간에도 신청되거나, 동시에 누른 두 신청이 모두 통과하고, 같은 시간에 여러 고객사가 '접수 완료' 메일을 받는 문제가 생김.
- **무엇**: ① 신청 시 `TourBusy` 에 `Kind = 대기` 행으로 **자리를 먼저 잡음**(웹은 대기 건도 그 시간을 차지) ② [신청하기] 순간 `TourBusy` 를 **다시 읽어 확인** ③ 자리를 쓴 뒤 다시 읽어 **ID 가 작은(먼저 저장된) 쪽만 남기고** 진 쪽은 자리를 지우고 '다른 시간을 골라 주세요' 안내 ④ 거절 · 취소(관리자) · 신청 취소(내 신청) 시 대기 자리 해제 ⑤ 승인 시 `대기` 행을 관리자 행(`예약`)으로 교체.
- **어디에**: `scrBook.yaml` `btnNext.OnSelect`, `scrAdmin.yaml` 승인 · 거절 · 취소, `scrMy.yaml` `btnMyCancel`.
- **주의**: **SharePoint `TourBusy` 권한 변경 필수** — 신청자가 행을 추가하므로 "모든 항목 읽기 / 자기가 만든 항목만 편집"(README 3-4절, `provision.ps1`). 한 사람이 여러 건을 걸면 다른 사람 일정이 실제로 막히므로 F-08(경고문) · 6장 3번(건수 제한) 결정과 연결. 한계: 잠금이 아니라 '먼저 저장된 쪽 우선' 방식(동시에 눌러도 한 건만 남지만 진 쪽은 저장 직후 안내를 받음).

## 7. 통계 화면 UX 검토 (데이터 시각화 기준)

대상: `scrStats.yaml`. 기준: 차트 형태 선택 · 색 사용 · 마크 · 접근성 점검 항목(막대 · 색 · 라벨 · 표 보기). 결과는 P-07 에 반영돼 있음. 아래 화면 확인은 YAML 로 그린 **개략도**이며 실제 Power Apps 렌더링과 다를 수 있음.

### 7-1. 현황 (10/13 컨버전 버전)

- 가로 막대 목록 **8개**(센터 · 투어 종류 · 방문 유형 · 방문 목적 · 업종 · 담당(실) · 언어 · 직무) + 월별 세로 막대 1개 + KPI 4개가 **탭 3개 뒤에** 나뉘어 있음.
- 모든 카드가 **높이 470px 고정**인데 목록은 3~5행인 곳이 많아(센터 3 · 방문 유형 4 · 방문 목적 5 · 언어 4) 카드 대부분이 비어 있음.
- 막대가 모두 **가장 진한 색(near-black)** 한 가지: 8개 목록이 한꺼번에 보이면 무겁고, 어떤 값이 중요한지 구분이 안 됨.
- 막대 옆 숫자는 **건수만**, 비율이 없음. 업종만 값순, 나머지는 고정 순서.
- **계산 중복**: 행마다 `CountRows(Filter(Filter(Filter(colStatAll …))))` 로 기간 · 집계 기준 필터를 **행 수만큼 반복** (업종 14행 → 14번 전체 스캔 …). 탭을 없애 한 화면에 모두 그리면 이 반복이 한꺼번에 계산됨.

### 7-2. 판단과 조치

| # | 점검 | 판단 | 조치 (P-07) |
| --- | --- | --- | --- |
| 1 | 형태: 순서 없는 범주(업종 · 담당 · 직무)의 크기 비교 | **가로 막대가 맞음**(긴 이름, 값순 정렬 가능). 원형 · 도넛은 부적합 | 유지 |
| 2 | 형태: 월별 추이 | 세로 막대(시간순)가 맞음 | 유지 |
| 3 | 탭으로 나눔 | 3번 눌러야 전체 파악. 스크롤이 가능해졌으므로 숨길 이유 없음 | **탭 제거 · 한 화면(스크롤)**: 추이 · 센터 → 방문 구성(유형 · 목적 · 언어) → 분포(업종 · 담당 · 직무) 3줄 |
| 4 | 카드 높이 | 3~5행 목록에 470px = 빈 공간 | 줄별로 높이를 내용에 맞춤 (250 / 390), 같은 줄 카드는 같은 높이 |
| 5 | 색: 단일 계열(한 가지 색) 막대 | 한 색은 맞지만 **전부 진하면** 중요도 구분 불가. '하나가 핵심이면 강조(emphasis)' 가 정석 | **가장 큰 항목만 진하게**(`cPrimary`), 나머지는 보조색(`cInk2`). 막대와 바탕 대비 3:1 이상 |
| 6 | 색: 식별 가능한 항목(투어 종류) | 색이 **항목을 따라야** 함 (순위 따라 바뀌면 안 됨) | 투어 종류 막대는 **투어 색**(달력 · 칩과 같은 색)으로 |
| 7 | 정렬 | 순서 없는 범주는 값 큰 순 (웹 F-09 와 일치) | 방문 유형 · 목적 · 언어 · 직무 · 투어 · 센터 값순, **담당(실)은 '기타' 를 맨 아래** |
| 8 | 값 표기 | 막대 끝에 값을 직접 표기(툴팁 없는 환경이므로 필수). 건수만으로는 비중을 알기 어려움 | **`N건 · P%`** 로 표기 (비율 = 항목 건수 ÷ 목록 합계) |
| 9 | 마크 | 얇은 막대(8px)와 옅은 트랙, 격자선 없음 | 유지 |
| 10 | 계산 | 행마다 전체 스캔 | 기간 · 집계 기준 필터를 **목록당 1번**(`base`)으로 줄이고 정렬 · 합계(`Tot`)를 같은 계산에서 구함 |
| 11 | 데이터 양 | 한 번에 읽으면 2000행 제한 | 해마다 나눠 읽음 (이미 10/19 반영) |

### 7-3. 아직 하지 않은 것 · 권장 (개발자 판단)

| 항목 | 이유 · 제안 |
| --- | --- |
| **표 보기**(차트와 같은 값을 표로) | 모든 차트에 표 보기 쌍이 있어야 접근성이 충족됨. Power Apps 는 `표로 보기` 토글(`gStatTable`) + `Table` 컨트롤로 구현 가능. 지금은 막대 옆 값 표기와 엑셀 내보내기(범위 밖)로 대체 |
| **방문 유형 · 언어를 누적 막대 1개로** | 4~5개로 구성비를 보는 용도라 가로 막대 4줄보다 100% 누적 막대 1줄이 공간 대비 효과적. 파트너사(F-02)가 추가되면 5개 → 색 5개 필요 |
| 업종 **0건 표시** | 웹은 모든 업종을 0 건 포함 표시(F-01 · F-09). 현재 `N > 0` 로 숨김. 업종을 9종으로 줄인 뒤 전부 표시하면 항상 같은 위치 → 비교 쉬움 |
| 통계 **그리드(히트맵) 표** | 웹 전용. 범위 밖 |
| 마우스 올림 툴팁 | Power Apps 캔버스는 호버 툴팁이 없어 값을 직접 표기로 해결(위 8) |
| 색상 팔레트 검증 | 강조(검정 + 보조색)와 투어 6색이 색각이상에서 구분되는지는 값 표기 · 정렬 · 라벨이 함께 있어 **색만으로 구분하지 않음**. 투어 색 자체의 검증은 디자인 시스템 팔레트 기준으로 별도 확인 권장 |

### 7-4. 확인 방법 (개발자 · 운영자)

1. 통계 화면을 열어 탭 없이 **스크롤 한 번으로 모든 카드가 보이는지**.
2. 값이 모두 0 이어도 **레이아웃이 깨지지 않는지**(최대값 0 → 막대 폭 0, 비율 표기 생략).
3. 기간을 `전체 기간` 으로 바꿨을 때 **응답 시간**(체감) — 계산 중복 제거 효과는 **실측하지 못함**. 느리면 `colStatAll` 에 필요한 열만 남기거나 월별 집계 목록으로 미리 계산.
4. 가장 큰 항목이 **한 개만** 진하게, 동률이면 모두 진하게 보임(동률 처리: `N = Mx`).
