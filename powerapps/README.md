# TDL 방문 예약 → Power Apps 이전 가이드

지금 운영 중인 웹 예약 사이트(GitHub Pages + Google Apps Script + Google 시트)를
**회사 Microsoft 365 안으로** 옮기는 작업입니다. 개인정보가 외부 서비스(Google)를 거치지 않게 하는 것이 목적입니다.

| 지금 (웹) | 이전 후 (사내) |
| --- | --- |
| React 웹페이지 (`/reserve/`, `/admin/`) | **Power Apps 캔버스 앱** 1개 (신청 · 내 신청 · 관리자 화면) |
| Google 시트 | **SharePoint 목록** 4개 |
| Apps Script `MailApp` | **Power Automate** 흐름 4개 + Outlook |
| 신청자가 참석자 명단을 대신 입력 | **Microsoft Forms** 링크로 참석자가 직접 입력 · 동의 (사업개선팀 결정) |

---

## 0. 먼저 답: "HTML 기반이 맞나요?" → 아니요

Power Apps 캔버스 앱은 **HTML 이 아닙니다.** 파워포인트처럼 화면에 컨트롤(레이블 · 버튼 · 입력칸 · 갤러리)을 올리고,
각 컨트롤의 속성에 **엑셀 수식 같은 Power Fx** 를 적어서 만듭니다.

- 그래서 지금의 `index.html` 이나 React 코드를 Power Apps 에 **그대로 업로드할 수는 없습니다.**
- 대신 이 폴더에 **붙여넣기만 하면 화면이 생기는 코드(YAML)** 를 만들어 두었습니다. 화면 6개를 각각 복사 → 붙여넣기 하면 됩니다.
- 참고: React 코드를 그대로 올리는 'Power Apps 코드 앱(Code apps)' 이라는 방식도 있지만, 개발 도구(Node · PAC CLI) 설치와
  관리자 설정이 필요하고 사용자마다 프리미엄 라이선스가 필요합니다. 초보자 · 표준 라이선스 기준으로는 **캔버스 앱이 맞습니다.**

이 구성은 SharePoint · Outlook · Forms · Office 365 Users **표준 커넥터만** 씁니다. 회사 M365 라이선스에 포함된 Power Apps 권한으로 충분하고
프리미엄 라이선스는 필요 없습니다.

┌──────────────────────┐   ② Run   ┌──────────────────────┐   │

└──────┬───────────────┘                                     ┌──────────────────────┐
       │ 읽기/쓰기                                            │ 흐름 B 응답 모으기     │ ◄── ⑤ Forms 새 응답
       ▼                                                      └─────────┬────────────┘
┌──────────────────────────── SharePoint 사이트 ────────────────────────▼───────────┐

> **시화MTV 는 현재 닫혀 있습니다** (웹 배포 2026-10-12, `MTV_ENABLED = false`).
> Power Apps 쪽도 `App.Formulas` 의 **`MtvEnabled = false`** 로 같게 맞췄습니다.
> - 신청 화면에는 TDL Lab · 메가와이즈 센터 · 메가와이즈 + TDL Lab **3가지 투어만** 보입니다.
> - `TourAdmins` 에 `mtv` · `hq` 로 등록된 사람은 관리자 화면에 들어올 수 없습니다 (웹의 '준비 중' 페이지와 같음).
> - 일정 막기 창의 '시화MTV' 는 눌리지 않습니다.
> - 열 때는 `MtvEnabled = true` 한 줄만 바꾸고 App → OnStart 실행. 시간표 · 3영업일 규칙 · 센터별 승인 · 흐름은 모두 이미 들어 있습니다.

## 3. 1단계 — SharePoint 목록 만들기 (약 20분)

### 3-1. 사이트 만들기
1. SharePoint 홈 → **+ 사이트 만들기** → **팀 사이트** → 이름 `TDL 방문관리`, 개인 정보 설정 **비공개**
2. 만든 사이트 주소를 메모해 둡니다. 예) `https://회사.sharepoint.com/sites/TDLVisit`

### 3-2. CSV 로 목록 4개 만들기 (가장 쉬움)
`1-sharepoint` 폴더의 CSV 하나가 목록 하나입니다. 첫 줄이 열 이름, 둘째 줄은 **열 형식을 알려주는 샘플 행**입니다.

1. 사이트 → **+ 새로 만들기** → **목록** → **CSV에서** (메뉴에 없으면 '기존 목록에서/Excel에서' 를 고르고 CSV 를 엑셀로 저장해 사용)
2. `VisitRequests.csv` 업로드 → 미리 보기에서 **열 형식**을 아래처럼 맞춥니다.
   - `Title` 열이 목록의 **제목(Title)** 으로 연결되었는지 확인
   - 숫자: `CFrom` `CTo` `LFrom` `LTo` `MFrom` `MTo` `ExpectedHeadcount` `AttendeeCount`
   - 날짜(시간 없음): `VisitDate` / 날짜 + 시간: `ConsentAt`
   - 나머지는 모두 **한 줄 텍스트**
3. 목록 이름은 파일 이름 그대로 `VisitRequests` 로 만듭니다. (**영문 이름 그대로** 써야 앱 수식이 맞습니다)
4. 만든 뒤 **목록 설정**에서 `HostComment` · `AdminMemo` · `FormsLink` 열을 **여러 줄 텍스트**로 바꿉니다 (255자 제한 해제).
5. 샘플 행은 **삭제**합니다.
6. 같은 방법으로 `VisitAttendees` (숫자 없음, `ConsentAt` 날짜+시간, `VisitDate` 날짜) · `TourBusy` (`CFrom`~`MTo` 숫자) · `TourAdmins` 를 만듭니다.

> 열 이름에 한글을 쓰지 않는 이유: SharePoint 는 한글 열 이름을 `_x00b0_…` 같은 내부 이름으로 바꿔서 수식이 길고 헷갈립니다.
> 화면에 보이는 글자는 앱이 한글로 보여 주니 목록은 영문으로 둡니다. 목록 화면에서 보기 편하려면 열의 '표시 이름'만 한글로 바꿔도 됩니다(내부 이름은 그대로 유지됨).

IT 팀이 PnP PowerShell 을 쓸 수 있다면 `provision.ps1` 로 4개 목록 · 인덱스 · 권한을 한 번에 만들 수 있습니다.

### 3-3. 관리자 등록 — `TourAdmins`

| --- | --- |
| center.manager@회사.com | `main` (메가와이즈 · TDL Lab) |

### 3-4. 권한 (개인정보 보호의 핵심)
| 목록 | 일반 직원 (신청자) | 센터 관리자 |
| --- | --- | --- |
| VisitRequests | 추가 · 편집 (아래 '항목 수준 권한' 권장) | 전체 편집 |
| **VisitAttendees** | **접근 없음** | 읽기 · 편집 |
| TourBusy | 읽기 + **추가 · 자기 항목만 편집** (아래) | 전체 편집 |
| TourAdmins | 읽기 | 읽기 (편집은 운영 책임자만) |

- **VisitAttendees 권한 끊기**: 목록 → ⚙ → 목록 설정 → **이 목록에 대한 사용 권한** → **권한 상속 중지** → 구성원 그룹 삭제, 관리자만 남기기
- **TourAdmins**: 같은 방법으로 상속을 끊고 구성원은 **읽기**만
- **TourBusy**: 신청자가 신청할 때 그 시간을 '대기' 로 잡아 두므로 구성원도 **추가**할 수 있어야 합니다.
  목록 설정 → **고급 설정** → 읽기 권한 `모든 항목`, 만들기 및 편집 권한 `사용자가 만든 항목만`.
  (신청자는 자기가 잡은 '대기' 행만 지울 수 있고, 승인된 예약 · 막힌 일정은 관리자 계정이 만든 행이라 건드릴 수 없습니다)
- **VisitRequests 항목 수준 권한**(권장): 목록 설정 → **고급 설정** → 읽기 권한 `사용자가 만든 항목만`, 만들기 및 편집 권한 `사용자가 만든 항목만`.
  이렇게 하면 신청자는 자기 신청만 봅니다. 관리자는 사이트 **소유자** 그룹에 넣어야 전체가 보입니다.
  (다른 사람 예약과 겹치는지는 개인정보가 없는 `TourBusy` 로 판정하므로 신청자가 남의 신청을 볼 필요가 없습니다)
- 흐름 B(Forms → VisitAttendees)를 만드는 사람은 관리자여야 합니다 (흐름은 만든 사람 권한으로 실행됩니다).

## 5. 3단계 — 앱 만들기

### 5-1. 시작 화면에서 무엇을 고르나
make.powerapps.com → **만들기** 에 보이는 선택지:

| 선택지 | 하는 일 | 이번 작업 |
| --- | --- | --- |
| 데이터에서 시작 | 목록 하나로 '목록 · 상세 · 편집' 3화면 앱을 자동 생성 | 화면이 정해진 틀이라 **안 맞음** |
| 디자인(페이지 디자인)에서 시작 | 미리 만든 화면 틀 고르기 | 틀을 지우는 일이 더 많아 **안 맞음** |
| **빈 앱 → 빈 캔버스 앱** | 빈 화면에서 직접 구성 | **이걸 고르세요** |

1. **빈 앱** → **빈 캔버스 앱** → 이름 `TDL 방문 예약`, 형식 **태블릿** → 만들기
2. 언어 · 지역 묻는 창이 나오면 한국어 그대로

### 5-2. 화면 크기 1366 × 768 맞추기 (줄이지 않고 스크롤)
1. 위 메뉴 **설정(⚙)** → **디스플레이**
2. **화면 크기 + 방향**: `사용자 지정` → 너비 `1366`, 높이 `768`
3. **크기 조정**(Scale to fit) **끄기**, **가로 세로 비율 잠금** **끄기**, 방향 잠금 켜기
4. **설정 → 일반 → 데이터 행 제한**: `2000` (기본 500)

왜 '크기 조정' 을 끄나요? 1366×768 노트북에서 실제로 앱이 쓸 수 있는 높이는 768 이 아닙니다.

| 빼야 하는 것 | 높이 |
| --- | --- |
| Windows 작업 표시줄 | 약 40 |
| 브라우저 탭 · 주소창 | 약 80 |
| Power Apps 플레이어 위쪽 막대 (`hidenavbar=true` 로 없앨 수 있음, 9단계) | 약 48 |
| **앱이 쓸 수 있는 높이** | **약 600 ~ 650** |

크기 조정을 켜 두면 앱 전체가 600/768 ≈ **78%** 로 줄어 9pt 글자가 약 9px 로 보이고, 좌우에 빈 띠가 생깁니다.
크기 조정을 끄면 글자는 **원래 크기 그대로**, 위 메뉴와 (신청 화면의) [이전] · [다음] 버튼은 **고정**,
가운데 본문만 위아래로 스크롤됩니다. 웹 버전에서 페이지를 스크롤하는 것과 같은 사용감입니다.

- 이를 위해 화면마다 **Width = `sw`, Height = `sh`** 를 넣습니다 (5-5, 각 YAML 맨 위 `#` 줄). `sw` · `sh` · `ox` 는 `App.Formulas` 에 있습니다.
- 각 화면의 본문은 `con?Body`(세로 자동 레이아웃 컨테이너, 넘치면 스크롤) 안의 `con?Page`(1366 폭 고정 틀)에 들어 있습니다.
  화면을 고칠 때는 `con?Page` 안에서 지금처럼 X · Y 좌표로 배치하면 됩니다.
- 창이 1366 보다 넓으면 화면이 가운데에 놓이고, 좁으면(예: Teams 탭) 가로 스크롤이 생깁니다. **Teams 탭보다 브라우저 링크를 권장**합니다.

메모장의 **바꾸기**(Ctrl+H)로 YAML 안의 버전 번호를 고친 뒤 다시 붙여넣으세요.

## 12. 웹 버전 대비 운영 위험과 보완 내용

웹(Apps Script)은 서버에서 **잠금(LockService) 안에서** 겹침을 다시 확인하고 저장했습니다. Power Apps 는 서버 코드가 없고
각자의 브라우저에서 수식이 실행되므로, 그대로 옮기면 아래 문제가 생깁니다. 이 폴더의 수식은 모두 보완해 두었습니다.

| # | 위험 (보완 전) | 실제로 생기는 일 | 보완 |
| --- | --- | --- | --- |
| 1 | 대기 중인 신청이 시간을 차지하지 않음 | 같은 시간에 여러 고객사가 '접수 완료' 메일을 받고, 한 곳만 승인 · 나머지는 거절 | 신청 시 `TourBusy` 에 `대기` 행으로 자리를 잡음 (웹과 같은 규칙) |
| 2 | 신청 직전에 다시 확인하지 않음 | 달력을 연 뒤 다른 사람이 잡은 시간에도 신청됨 | [신청하기] 순간 SharePoint 를 다시 읽어 확인 |
| 3 | 동시에 누른 두 신청 | 둘 다 통과 | 자리를 먼저 쓰고 다시 읽어 **ID 가 작은(먼저 저장된) 쪽만** 남김 (잠금 대신 쓰는 방식) |
| 4 | 신청번호 `V년월일-시분초` | 같은 초에 들어온 두 신청이 같은 번호 → Forms 참석자가 엉뚱한 신청에 붙음 | 번호 뒤에 무작위 4자리 (`V261021-143015-7F3A`) |
| 5 | 버튼 연속 클릭 | 신청 2건 · 승인 메일 2통 · 점유 행 2개 | 처리 중에는 버튼 잠금 ('저장 중…') |
| 6 | 메일 흐름 실패를 모름 | 화면엔 '발송됩니다', 실제론 메일 없음 (흐름 소유자 퇴사 · 연결 만료 때 흔함) | 흐름 실패 시 노란 경고로 알림 |
| 7 | 복합 투어 두 센터가 동시에 승인 | 서로의 승인을 '대기' 로 덮어써 영원히 대기 | 자기 센터 칸만 저장 + 둘 다 승인이면 바로 확정 |
| 8 | 다른 관리자가 이미 처리한 건 | 거절된 건을 다시 승인 | 누르는 순간 최신 상태를 다시 읽어 막음 |
| 9 | 통계를 한 번에 읽음 | 2000행을 넘으면 앞 2000행만 집계 (경고 없음) | 해마다 나눠 읽기 |

## 13. 확인하지 못한 것 (솔직하게)

이 저장소 환경에는 Power Apps 가 없어서 **YAML 붙여넣기와 수식을 실제 Power Apps Studio 에서 실행해 보지는 못했습니다.**
YAML 구조 · 컨트롤 이름 중복 · 수식 괄호는 스크립트로 검사했고, 화면 배치는 `mockup/index.html` 과 같은 좌표입니다.
컨트롤 버전 번호나 일부 속성 이름이 회사 Power Apps 버전과 다르면 5-5 의 '버전 오류' 방법으로 맞춰 주세요.
특히 이번 보완에서 처음 쓰는 아래 부분은 붙여넣은 뒤 꼭 확인해 주세요.
- 본문 스크롤 컨테이너 `con?Body` 의 `Variant: AutoLayout` · `LayoutOverflowY` 속성. 붙여넣기에서 오류가 나면 **세로 컨테이너**를 하나 직접 추가해
  코드 보기로 이름을 확인하고 바꾸거나, 직접 추가한 세로 컨테이너(스크롤 켜기)에 `con?Page` 를 옮겨 넣으면 됩니다.
- 이름 붙인 수식에서 `App.Width` · `App.Height` 를 쓰는 `sw` · `sh`. 오류가 나면 각 화면의 `sw` → `Max(App.Width, 1366)`, `sh` → `Max(App.Height, 480)` 로 바꿉니다.
처음 붙여넣을 때 막히는 오류 문구를 알려 주시면 바로 고쳐 드리겠습니다.

## 14. Power Apps 전용 기능 표시 규칙 (`[PA 전용]`)

웹앱(React + Apps Script)에는 없고 **Power Apps 에만 있는 기능**은 모두 `[PA 전용]` 으로 표시합니다.
다른 개발자가 "웹에도 있나? 웹을 고치면 여기도 고쳐야 하나?" 를 바로 알 수 있게 하기 위해서입니다.

| 어디에 | 어떻게 |
| --- | --- |
| 화면 YAML 맨 위 `#` 머리말 | `── [PA 전용] ──` 아래에 그 화면의 전용 기능 목록 (붙여넣으면 앱에는 안 들어가는 저장소용 설명) |
| 수식 안 (Power Fx 주석) | 여러 줄 수식은 맨 앞 줄 `// [PA 전용] 무엇 · 웹은 어떻게`, 한 줄 수식은 끝에 `// [PA 전용] …`. 앱에 붙여넣은 뒤에도 Studio 에서 보입니다 |
| `App.Formulas` · `App.OnStart` | 해당 이름 위 주석 `// [PA 전용] …` |
| 흐름 (`flows.md`) | 표의 흐름 이름 옆 **[PA 전용]** |

찾기: 저장소에서 `grep -rn "PA 전용" powerapps/`, Power Apps Studio 에서는 **검색(돋보기)** 에 `PA 전용`.

**수정할 때 지킬 것**
1. Power Apps 에 웹에 없는 기능을 넣거나 바꾸면 → 수식에 `// [PA 전용] 무엇을 하는지 · 웹은 어떻게 하는지(없으면 '웹에는 없음')` 주석, 그 화면 YAML 머리말 목록, 아래 표를 **함께** 고칩니다.
2. 나중에 웹에도 같은 기능이 생기면 → `[PA 전용]` 표시를 지우고 아래 표에서 뺍니다.
3. 반대로 웹에만 있고 Power Apps 에 아직 없는 기능은 12절 '남는 차이' 목록에 적습니다.
