# TDL 방문 예약 → Power Apps 이전 가이드

지금 운영 중인 웹 예약 사이트(GitHub Pages + Google Apps Script + Google 시트)를
**회사 Microsoft 365 안으로** 옮기는 작업입니다. 개인정보가 외부 서비스(Google)를 거치지 않게 하는 것이 목적입니다.

| 지금 (웹) | 이전 후 (사내) |
| --- | --- |
| React 웹페이지 (`/reserve/`, `/admin/`) | **Power Apps 캔버스 앱** 1개 (신청 · 내 신청 · 관리자 화면) |
| Google 시트 | **SharePoint 목록** 4개 |
| Apps Script `MailApp` | **Power Automate** 흐름 4개 + Outlook |
| 신청자가 참석자 명단을 대신 입력 | **Microsoft Forms** 링크로 참석자가 직접 입력 · 동의 (사업개선팀 결정) |

---

## 0. 먼저 답: "HTML 기반이 맞나요?" → 아니요

Power Apps 캔버스 앱은 **HTML 이 아닙니다.** 파워포인트처럼 화면에 컨트롤(레이블 · 버튼 · 입력칸 · 갤러리)을 올리고,
각 컨트롤의 속성에 **엑셀 수식 같은 Power Fx** 를 적어서 만듭니다.

- 그래서 지금의 `index.html` 이나 React 코드를 Power Apps 에 **그대로 업로드할 수는 없습니다.**
- 대신 이 폴더에 **붙여넣기만 하면 화면이 생기는 코드(YAML)** 를 만들어 두었습니다. 화면 5개를 각각 복사 → 붙여넣기 하면 됩니다.
- 참고: React 코드를 그대로 올리는 'Power Apps 코드 앱(Code apps)' 이라는 방식도 있지만, 개발 도구(Node · PAC CLI) 설치와
  관리자 설정이 필요하고 사용자마다 프리미엄 라이선스가 필요합니다. 초보자 · 표준 라이선스 기준으로는 **캔버스 앱이 맞습니다.**

이 구성은 SharePoint · Outlook · Forms · Office 365 Users **표준 커넥터만** 씁니다. 회사 M365 라이선스에 포함된 Power Apps 권한으로 충분하고
프리미엄 라이선스는 필요 없습니다.

```

┌──────────────────────┐   ② Run   ┌──────────────────────┐   │
│ Power Apps 캔버스 앱 │ ────────► │ 흐름 A 접수 메일       │ ──┘ ③ 신청자 · 참석자에게 Forms 링크
│ 신청 · 내 신청 · 관리자│           └──────────────────────┘
└──────┬───────────────┘                                     ┌──────────────────────┐
       │ 읽기/쓰기                                            │ 흐름 B 응답 모으기     │ ◄── ⑤ Forms 새 응답
       ▼                                                      └─────────┬────────────┘
┌──────────────────────────── SharePoint 사이트 ────────────────────────▼───────────┐
│ VisitRequests (신청)   VisitAttendees (참석자 · 관리자만)   TourBusy (점유 · 막기)   │
│ TourAdmins (관리자 명단)                                                          │
└──────────────────────────────────────────────────────────────────────────────────┘
       ▲ ⑥ 관리자가 승인 · 거절 → 흐름 C 결과 메일          흐름 D: 1년 지난 참석자 정보 자동 삭제
```

> **시화MTV 는 현재 닫혀 있습니다** (웹 배포 2026-10-12, `MTV_ENABLED = false`).
> Power Apps 쪽도 `App.Formulas` 의 **`MtvEnabled = false`** 로 같게 맞췄습니다.
> - 신청 화면에는 TDL Lab · 메가와이즈 센터 · 메가와이즈 + TDL Lab **3가지 투어만** 보입니다.
> - `TourAdmins` 에 `mtv` · `hq` 로 등록된 사람은 관리자 화면에 들어올 수 없습니다 (웹의 '준비 중' 페이지와 같음).
> - 일정 막기 창의 '시화MTV' 는 눌리지 않습니다.
> - 열 때는 `MtvEnabled = true` 한 줄만 바꾸고 App → OnStart 실행. 시간표 · 3영업일 규칙 · 센터별 승인 · 흐름은 모두 이미 들어 있습니다.

## 3. 1단계 — SharePoint 목록 만들기 (약 20분)

### 3-1. 사이트 만들기
1. SharePoint 홈 → **+ 사이트 만들기** → **팀 사이트** → 이름 `TDL 방문관리`, 개인 정보 설정 **비공개**
2. 만든 사이트 주소를 메모해 둡니다. 예) `https://회사.sharepoint.com/sites/TDLVisit`

### 3-2. CSV 로 목록 4개 만들기 (가장 쉬움)
`1-sharepoint` 폴더의 CSV 하나가 목록 하나입니다. 첫 줄이 열 이름, 둘째 줄은 **열 형식을 알려주는 샘플 행**입니다.

1. 사이트 → **+ 새로 만들기** → **목록** → **CSV에서** (메뉴에 없으면 '기존 목록에서/Excel에서' 를 고르고 CSV 를 엑셀로 저장해 사용)
2. `VisitRequests.csv` 업로드 → 미리 보기에서 **열 형식**을 아래처럼 맞춥니다.
   - `Title` 열이 목록의 **제목(Title)** 으로 연결되었는지 확인
   - 숫자: `CFrom` `CTo` `LFrom` `LTo` `MFrom` `MTo` `ExpectedHeadcount` `AttendeeCount`
   - 날짜(시간 없음): `VisitDate` / 날짜 + 시간: `ConsentAt`
   - 나머지는 모두 **한 줄 텍스트**
3. 목록 이름은 파일 이름 그대로 `VisitRequests` 로 만듭니다. (**영문 이름 그대로** 써야 앱 수식이 맞습니다)
4. 만든 뒤 **목록 설정**에서 `HostComment` · `AdminMemo` · `FormsLink` 열을 **여러 줄 텍스트**로 바꿉니다 (255자 제한 해제).
5. 샘플 행은 **삭제**합니다.
6. 같은 방법으로 `VisitAttendees` (숫자 없음, `ConsentAt` 날짜+시간, `VisitDate` 날짜) · `TourBusy` (`CFrom`~`MTo` 숫자) · `TourAdmins` 를 만듭니다.

> 열 이름에 한글을 쓰지 않는 이유: SharePoint 는 한글 열 이름을 `_x00b0_…` 같은 내부 이름으로 바꿔서 수식이 길고 헷갈립니다.
> 화면에 보이는 글자는 앱이 한글로 보여 주니 목록은 영문으로 둡니다. 목록 화면에서 보기 편하려면 열의 '표시 이름'만 한글로 바꿔도 됩니다(내부 이름은 그대로 유지됨).

IT 팀이 PnP PowerShell 을 쓸 수 있다면 `provision.ps1` 로 4개 목록 · 인덱스 · 권한을 한 번에 만들 수 있습니다.

### 3-3. 관리자 등록 — `TourAdmins`

### 3-4. 권한 (개인정보 보호의 핵심)
| 목록 | 일반 직원 (신청자) | 센터 관리자 |
| --- | --- | --- |
| VisitRequests | 추가 · 편집 (아래 '항목 수준 권한' 권장) | 전체 편집 |
| **VisitAttendees** | **접근 없음** | 읽기 · 편집 |
| TourBusy | 읽기 | 편집 |
| TourAdmins | 읽기 | 읽기 (편집은 운영 책임자만) |

- **VisitAttendees 권한 끊기**: 목록 → ⚙ → 목록 설정 → **이 목록에 대한 사용 권한** → **권한 상속 중지** → 구성원 그룹 삭제, 관리자만 남기기
- **TourBusy · TourAdmins**: 같은 방법으로 상속을 끊고 구성원은 **읽기**만
- **VisitRequests 항목 수준 권한**(권장): 목록 설정 → **고급 설정** → 읽기 권한 `사용자가 만든 항목만`, 만들기 및 편집 권한 `사용자가 만든 항목만`.
  이렇게 하면 신청자는 자기 신청만 봅니다. 관리자는 사이트 **소유자** 그룹에 넣어야 전체가 보입니다.
  (다른 사람 예약과 겹치는지는 개인정보가 없는 `TourBusy` 로 판정하므로 신청자가 남의 신청을 볼 필요가 없습니다)
- 흐름 B(Forms → VisitAttendees)를 만드는 사람은 관리자여야 합니다 (흐름은 만든 사람 권한으로 실행됩니다).

## 5. 3단계 — 앱 만들기

### 5-1. 시작 화면에서 무엇을 고르나
make.powerapps.com → **만들기** 에 보이는 선택지:

| 선택지 | 하는 일 | 이번 작업 |
| --- | --- | --- |
| 데이터에서 시작 | 목록 하나로 '목록 · 상세 · 편집' 3화면 앱을 자동 생성 | 화면이 정해진 틀이라 **안 맞음** |
| 디자인(페이지 디자인)에서 시작 | 미리 만든 화면 틀 고르기 | 틀을 지우는 일이 더 많아 **안 맞음** |
| **빈 앱 → 빈 캔버스 앱** | 빈 화면에서 직접 구성 | **이걸 고르세요** |

1. **빈 앱** → **빈 캔버스 앱** → 이름 `TDL 방문 예약`, 형식 **태블릿** → 만들기
2. 언어 · 지역 묻는 창이 나오면 한국어 그대로

### 5-2. 화면 크기 1366 × 768 맞추기
1. 위 메뉴 **설정(⚙)** → **디스플레이**
2. **화면 크기 + 방향**: `사용자 지정` → 너비 `1366`, 높이 `768`
3. **크기 조정**(Scale to fit) **켜기**, **가로 세로 비율 잠금** **켜기**, 방향 잠금 켜기
   → 1366×768 노트북의 브라우저는 주소창 때문에 실제 높이가 650px 정도라, 앱이 비율을 지키며 살짝 줄어 딱 맞게 들어갑니다.
4. **설정 → 일반 → 데이터 행 제한**: `2000` (기본 500)

### 5-3. 데이터 연결
왼쪽 **데이터(원통 아이콘)** → **데이터 추가**
1. `SharePoint` 검색 → 연결 → 사이트 주소 입력 → `VisitRequests`, `VisitAttendees`, `TourBusy`, `TourAdmins` 4개 체크 → 연결
2. 다시 데이터 추가 → `Office 365 사용자`(Office 365 Users) 추가

### 5-4. 공통 수식 붙여넣기
1. 왼쪽 **트리 뷰** 맨 위 **App** 클릭
2. 위쪽 **속성 드롭다운**(fx 왼쪽, 처음엔 `OnStart`)에서 **Formulas** 선택 → 수식 입력줄에 `App.Formulas.txt` 전체 붙여넣기
   - 맨 위 `FormsPrefillUrl` 을 4단계에서 복사한 미리 채워진 링크로 바꿉니다 (`REQNO` 포함)
3. 속성 드롭다운 **OnStart** → `App.OnStart.txt` 붙여넣기
4. 속성 드롭다운 **StartScreen** → 아래 붙여넣기 (화면 5개를 만든 뒤에 해야 오류가 없어집니다)
   ```
   If(!IsBlank(Param("requestNo")), scrAdmin, scrBook)
   ```

> Formulas 속성이 안 보이면: 설정 → **예정된 기능**(Upcoming features) → '이름 붙인 수식(Named formulas)' 을 켜세요.

### 5-5. 화면 5개 붙여넣기
각 YAML 파일 맨 위 `#` 줄에 그 화면의 **Fill · OnVisible** 값이 적혀 있습니다. 화면마다:

1. 트리 뷰 **+ 새 화면** → **빈 화면** → 이름을 파일 이름과 같게 (`scrBook`, `scrDone`, `scrMy`, `scrAdmin`, `scrStats`)
2. 화면을 선택하고 속성 드롭다운에서 `Fill` = `cBg`, `OnVisible` = 파일 맨 위에 적힌 값
3. YAML 파일을 메모장으로 열어 **전체 선택 → 복사**
4. 트리 뷰에서 그 화면 이름을 **오른쪽 클릭 → 붙여넣기** (또는 화면 클릭 후 `Ctrl+V`)
5. 처음 만들어진 `Screen1` 은 삭제

순서는 **scrDone → scrMy → scrAdmin → scrStats → scrBook** 이 편합니다 (scrBook 이 다른 화면을 참조).
붙여넣은 직후 빨간 오류 표시가 몇 개 있어도 정상입니다. 화면을 다 붙이고, 흐름(7단계)을 연결하고,
App → `...` → **OnStart 실행** 을 누르면 대부분 사라집니다.

**붙여넣기가 안 될 때 (버전 오류)**: Power Apps 버전에 따라 컨트롤 버전 번호(`Label@2.5.1` 등)가 다를 수 있습니다.
같은 종류의 컨트롤을 하나 직접 추가 → 오른쪽 클릭 → **코드 보기**(또는 코드 복사)로 실제 버전을 확인하고,
메모장의 **바꾸기**(Ctrl+H)로 YAML 안의 버전 번호를 고친 뒤 다시 붙여넣으세요.

### 5-6. Power Fx 30초 기초 (초보자용)
- 모든 속성 값은 수식입니다. 글자는 `"따옴표"`, 숫자는 그냥 `10`, 색은 `cInk` 처럼 이름 붙인 수식.
- `Set(gStep, 2)` = 변수 gStep 에 2 저장 (앱 전체에서 사용). `;` 로 여러 동작을 이어 씁니다.
- `Patch(목록, 레코드, {열: 값})` = SharePoint 에 저장. `Filter(목록, 조건)` = 걸러서 읽기.
- 갤러리 = 반복되는 카드 목록. 안쪽에서 `ThisItem.열이름` 으로 한 줄의 값을 씁니다.
- 수식을 고쳤는데 결과가 이상하면 **F5**(미리 보기)로 실행해 보고, 빨간 밑줄에 마우스를 올려 오류 문구를 읽어 보세요.

## 8. 6단계 — 테스트 (꼭 이 순서로)

1. 본인 메일을 `TourAdmins` 에 `main` 으로 등록 → 앱을 새로고침(OnStart 실행) → 상단에 **관리자** 메뉴가 보이는지
2. **방문 신청**: 메가와이즈 센터 투어 → 다음 주 수요일 → 13:00 → 정보 입력 → 참석자 이메일에 개인 메일 하나 → 신청하기
   - [ ] 완료 화면에 신청번호 · Forms 링크가 보임
   - [ ] 신청자 메일(A-1), 참석자 메일(A-2), 관리자 메일(A-3) 도착
   - [ ] SharePoint `VisitRequests` 에 1행
3. 받은 Forms 링크를 열어 신청번호가 자동으로 채워졌는지 확인 → 제출
   - [ ] `VisitAttendees` 에 1행, `VisitRequests` 의 `AttendeeCount` 가 1
   - [ ] 앱 **내 신청** 에서 `1 / 5명`
4. 관리자 메일의 버튼 → 앱이 관리자 화면 · 그 신청 건으로 열림 → **승인**
   - [ ] `TourBusy` 에 1행, 신청자 · 참석자 확정 메일 도착
   - [ ] 방문 신청 화면에서 같은 날짜 13:00 이 **마감**으로 보임
5. (시화MTV 를 연 뒤에만) 복합 투어(메가와이즈 + 시화MTV) 1건 → `main` 으로 승인 → 상태가 아직 **대기** →
   `TourAdmins` 에서 본인 Site 를 `mtv` 로 바꾸고 앱 새로고침 → 승인 → **승인** 으로 바뀌는지
6. 일정 막기 → 다음 주 금요일 종일 → 신청 화면에서 그 날이 **마감**
7. 상단 **통계** → `기간 지정` 으로 이번 달 1일~오늘 → 신청 건수 · 승인률 · 월별 추이가 맞는지, `전체 기간` 에서는 '비교 기간 없음' 이 나오는지
8. 다른 직원 계정으로 앱을 열어 **관리자 · 통계 메뉴가 안 보이는지**, SharePoint `VisitAttendees` 에 **접근이 안 되는지**

## 9. 7단계 — 게시 · 공유

1. 앱 오른쪽 위 **저장** → **게시**
2. make.powerapps.com → 앱 `...` → **공유** → 사용할 직원(또는 보안 그룹 · 전 직원 그룹) 추가.
   공유 창에서 **데이터 권한도 함께 부여** 하지 말고, 3-4 의 SharePoint 권한을 따로 맞춥니다.
3. 앱 **웹 링크**를 사내 공지 · 메일 서명 · Teams 탭에 겁니다. (Teams 채널 → `+` → Power Apps 로 탭 추가 가능)
4. 기존 GitHub Pages 예약 페이지에는 "사내 앱으로 이전되었습니다" 안내와 새 링크를 두고, 기존 Google 시트의 개인정보는
   이전이 끝나면 내려받아 보관 정책대로 처리하고 시트 · Apps Script 배포를 중지합니다.

## 11. 문제 해결

| 증상 | 원인 · 해결 |
| --- | --- |
| `TourBusy`, `VisitRequests` 이름에 빨간 줄 | 데이터 연결 이름이 다름. 5-3 에서 목록 이름을 정확히 연결했는지 확인 |
| 파란 밑줄 + '위임(delegation) 경고' | 목록이 2000행을 넘지 않으면 문제없음. 관리자 화면은 최근 180일만 불러옵니다 |
| 담당자 칸이 비어 있음 | App → `...` → OnStart 실행. 회사 프로필에 정보가 없으면 직접 입력 |
| 달력이 전부 흐림 | 투어를 먼저 고르세요. 시화MTV 투어는 3영업일 뒤부터 열립니다 |
| 날짜가 하루 밀려 보임 | 그래서 날짜 비교는 `DateKey`(텍스트) 로 합니다. SharePoint `VisitDate` 열은 '날짜만' 형식인지 확인 |
| Forms 링크에 신청번호가 안 채워짐 | `FormsPrefillUrl` 에 `REQNO` 가 들어 있는지 확인 |
| 흐름 실행 실패 | make.powerautomate.com → 흐름 → 실행 기록에서 빨간 단계를 열어 오류 확인 |
